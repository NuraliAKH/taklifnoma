# Задача 08 — Новые поля в редакторе (делать ПОСЛЕДНЕЙ, после 01–07)

Прочитай `prompts/templates/00_COMMON_RULES.md`.

Задачи 05, 06, 07 добавили в `SiteData` новые необязательные поля и секции. Их нужно вывести в редактор, иначе пользователь не сможет их заполнить.

## Сделай в `frontend/src/App.tsx` (только функции ниже, остальной код не трогай)
1. `getEditorFieldsForTemplate`:
   - семейство `malika`: поля `brideParents` («Родители невесты», placeholder «Akmal va Dilbar»), `brideFamily` («Фамилия семьи невесты», «Karimovlar»), `groomParents`, `groomFamily`; `loveStoryItems` — тип как `schedule` (список из `year`, `title`, `desc`), label «История любви — этапы».
   - семейство `envelope`: поле `wishText` (textarea, «Текст пожелания гостям»).
   - семейство `olive`: убедиться, что `photos` позволяет до 8 фото (2 для площадки/деталей + до 6 для галереи) — поменять `max: 2` на `max: 8` и label «Фото: 1-е — площадка, 2-е — детали, остальные — галерея».
2. `getTemplateSections`: для `olive` добавить `{ id: 'gallery', label: 'Фотогалерея' }` и `{ id: 'giftCard', label: 'Подарки и карта' }`.
3. Найди, как редактор рендерит поле типа `schedule`, и переиспользуй тот же UI для `loveStoryItems` (с полями год/заголовок/описание). Не пиши новый компонент, если можно параметризовать существующий.
4. Убедись, что новые поля сохраняются в заказ и приходят в `InvitationPage` в `data` (проверь путь данных: редактор → `POST` заказа → `GET` приглашения). Если бэкенд (`backend/src/orders`) хранит данные как JSON — менять бэкенд не нужно; если есть DTO с белым списком полей — добавь поля в DTO и напиши в отчёте.

## Критерии
- В редакторе шаблона ID 9 можно ввести родителей и этапы истории, они появляются в превью и на сайте.
- В шаблоне ID 8 можно изменить текст пожелания.
- Отчёт по формату.
